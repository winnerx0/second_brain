# Email Formatting

Use this skill whenever the user asks to draft, rewrite, polish, shorten, professionalize, soften, or prepare an email or email reply.

## Workflow

1. Identify the email purpose: ask, reply, update, apology, follow-up, scheduling, escalation, thank-you, or cold outreach.
2. Preserve the user's intent, facts, names, dates, and commitments. Do not invent details.
3. Choose a tone that matches the relationship and stakes. Default to warm, clear, and concise.
4. Produce a ready-to-send email unless the user asks for options or analysis.
5. If the email will be sent with a tool, show the final draft and get confirmation before sending.

## Structure

Prefer this shape:

```text
Subject: Clear subject line

Hi [Name],

[Opening context or acknowledgement.]

[Main point, request, update, or response.]

[Next step, deadline, availability, or call to action.]

Best,
[Sender]
```

For short or familiar emails, it is fine to omit the subject line or sign-off if the context makes them unnecessary.

## Style

- Keep paragraphs short: one idea per paragraph.
- Lead with the point. Avoid long warm-up.
- Make the ask explicit.
- Use plain language over corporate phrasing.
- Avoid over-apologizing. Use one direct apology when needed.
- Avoid filler like "I hope this email finds you well" unless the user specifically wants formal language.
- Avoid pressure-heavy phrases unless the situation is urgent.
- Prefer specific next steps over vague closings.

## Tone Defaults

- Professional: clear, respectful, compact.
- Friendly: warmer opening, still direct.
- Firm: calm, specific, no hostility.
- Apology: own the issue, state the fix, avoid excuses.
- Follow-up: brief context, clear reminder, easy next step.
- Cold outreach: short, relevant, low-friction ask.

## Output Rules

- If rewriting an email, return only the improved email unless the user asks for explanation.
- If key details are missing but a reasonable placeholder works, use bracketed placeholders like `[Tuesday at 2 PM]`.
- If the stakes are high or ambiguous, include a short note after the draft naming the assumption made.
- Never claim an attachment is included unless the user provided one or explicitly asked to mention it.
